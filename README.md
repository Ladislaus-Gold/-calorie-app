# Health

Личный дневник питания: вход через Google, продукты с КБЖУ на 100 г, расчёт по граммам,
сканер штрих-кодов, поиск в Open Food Facts, отчёты.
Хранение: Firebase (Authentication + Firestore). Хостинг: GitHub Pages.

## Файлы
- `index.html`, `style.css`, `app.js`, `starter.js` — само приложение (starter.js — набор базовых продуктов)
- `manifest.webmanifest`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png` — установка на экран телефона
- `firestore.rules` — правила доступа: каждый видит только свои данные

## Как обновить версию на GitHub
Репозиторий → Add file → Upload files → перетащить `index.html`, `app.js`, `style.css`, `starter.js`
(одноимённые файлы заменятся, `starter.js` добавится) → Commit changes. Через 1–2 минуты сайт обновится.
Если на телефоне виден старый вид: закрыть приложение полностью и открыть снова,
а при необходимости удалить значок с экрана «Домой» и добавить заново.

## Где что лежит в базе
- `products` — общая база продуктов (значения на 100 г, автор, штрих-код)
- `users/{uid}/entries` — записи дневника (дата, приём пищи, граммы, посчитанные КБЖУ)
- `users/{uid}/settings/profile` — дневная цель по калориям
- `users/{uid}/health/{дата}` и `users/{uid}/workouts/{id}` — данные из Apple Health (пишет Worker `health-ingest`)

## v31 — план и факт по БЖУ в каждом приёме пищи
- В карточке приёма пищи у белков, жиров и углеводов показано «факт из план» (например «Белки 12,3 из 40»). План приёма = суточная цель по БЖУ × доля приёма (завтрак/обед/ужин/перекус из «Я» → «Дневная цель»).
- Суточные граммы БЖУ приводятся к текущей цели по калориям (если калории в дневнике меняли вручную, граммы пересчитываются пропорционально), поэтому калории и граммы согласованы. Блок «Баланс БЖУ» использует те же цели.
- Перевыполнение (факт больше плана) выделяется красным и жирным: отдельный макроэлемент, калории приёма и значение в «Балансе БЖУ».
- Если профиль не заполнен и целей по БЖУ нет, показывается только факт, как раньше.
